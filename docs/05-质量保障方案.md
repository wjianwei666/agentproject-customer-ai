# 质量保障方案｜电商智能客服 Agent

> 角色：资深软件质量总监（20 年经验）
> 需求分类识别：**【测试体系搭建】** + **【需求质量管控】**（双分类，其余分类不适用）
> 团队适配：中型研发团队（1 全栈 + 1 产品 + 0.5 测试），不套用大厂重型流程

---

## 一、现状概述

| 项 | 现状 | 风险判断 |
|---|---|---|
| 研发模式 | 小步快跑，2.5 周出一期 | 迭代快，回归压力大 |
| 团队规模 | 1.5 人研发 + 0.5 测试 | 无专职自动化，必须靠脚本化 |
| 现有流程 | 无正式评审、无质量门禁 | 高风险 |
| 已有资产 | 23 条单元测试、30 条黄金评测集（待建） | 基础可用 |
| 核心质量特征 | **输出是非确定性文本**，不能用传统断言 | 这是本项目最大的质量难点 |

**关键认知**：这是 LLM 应用，质量保障对象不是"代码有没有 bug"，而是
**"输出的话术是否在允许的分布内"**。因此必须建立"确定性断言 + 语义评测"双层体系。

## 三、根因分析思路

严格区分**现象 / 直接原因 / 根本原因**（本方案强制要求）：

| 现象 | 直接原因 | 根本原因 | 对策层级 |
|---|---|---|---|
| 违规话术下发 | 合规规则漏配某条表述 | 规则库无变更评审机制，新增表述未入库 | 长期：规则库评审门禁 |
| 知识未命中却编造 | 提示词未强制"无知识不许答" | 提示词无版本管理，改动无评审 | 长期：提示词版本化 + 回归 |
| 人群匹配错误 | 权重配置过高 | 策略配置无灰度、无回滚演练 | 长期：配置灰度机制 |
| 意图识别退化 | 新增关键词抢占旧意图 | 缺少意图回归评测集 | 短期：黄金集扩到 30 条 |
| 上线后才发现问题 | 无预发环境验证 | 流程缺"准出门禁" | 长期：准出门禁 |

## 五、长期永久改进方案

### 5.1 质量门禁（CI/CD 四道闸）

```
提交 → [闸1] 单元测试 23 条全绿
     → [闸2] 黄金评测集 30 条通过率 ≥ 90%
     → [闸3] 合规零容忍：block 违规数必须 = 0
     → [闸4] 关键指标回归：意图准确率、Top1 命中率不下降 > 3%
     → 允许合并
```

**闸 3 是硬门禁**：只要黄金集里出现任何一条 block 级违规话术，直接阻断合并，
不接受"下次修"。这是本项目唯一不可协商的质量红线。

### 5.2 黄金评测集（30 条）

覆盖矩阵（6 画像 × 5 意图，按业务权重加权）：

| 维度 | 覆盖要求 | 条数 |
|---|---|---|
| 画像 | 6 个画像 + 兜底，每个 ≥ 4 条 | 28 |
| 意图 | 8 类全覆盖 | ≥ 24 |
| 合规 | 每条回复必须过 block 检查 | 30 |
| 转人工 | 覆盖 4 类触发条件 | ≥ 8 |
| 降级 | 无 LLM 模式全量跑一遍 | 30 |

**每条用例的断言四要素**：

| 断言 | 类型 | 示例 |
|---|---|---|
| 意图正确 | 确定性 | `intent == "logistics"` |
| 画像正确 | 确定性 | `persona_id == "anxious_urgent"` |
| 合规通过 | 确定性 | `no blocking issue` |
| 话术合规性 | 语义（LLM-as-judge 或人工） | 语气匹配画像、长度 60-180 字、无编造事实 |

### 5.3 缺陷分级规范

| 级别 | 定义 | 响应时限 | 示例 |
|---|---|---|---|
| P0 | 违规话术下发 / 优惠超发 / 服务不可用 | 2 小时内修复 | 回复出现"假一赔十" |
| P1 | 答非所问 / 画像错配 / 转人工未触发 | 1 个工作日 | 愤怒用户未升级 |
| P2 | 话术风格不符 / 内容不完整 | 3 个工作日 | VIP 被称呼"亲" |
| P3 | 文案措辞瑕疵 / 日志不规范 | 下个迭代 | 标点重复 |

## 八、预防机制与遗留风险

### 预防机制

1. **配置即代码**：人群策略、意图关键词、合规规则全部在 YAML，改动必须走 Git，可 diff、可回滚；
2. **提示词版本化**：`prompts/*.md` 每次改动必须附评测集对比结果；
3. **三重合规防线**：规则拦截 → LLM 整改 → 本地兜底替换，任一层失效仍有下一层；
4. **全链路 trace**：每条回复都可追溯意图、画像、知识、重试次数，便于事后复盘；
5. **降级可用**：LLM 不可用时链路仍完整，避免"断网即不可用"。

### 遗留风险（明确接受）

| 遗留风险 | 接受理由 | 缓解 |
|---|---|---|
| 语义质量依赖人工/LLM 评测，无法 100% 自动化 | 成本与收益权衡，一期人力不足 | 每迭代 50 条人工盲评 |
| BM25 在知识量 > 5000 chunk 时召回下降 | 一期知识量远小于该阈值 | 明确升级触发条件（见技术方案） |
| 无多轮上下文，重复问题需用户重述 | 一期产品范围明确不做 | 二期 F08 补 |
| 情绪标签依赖上游写入，可能缺失 | 缺失即兜底，不阻塞 | 二期接入会话情绪识别 |
