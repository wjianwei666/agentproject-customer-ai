## 二、四轮评审结论摘要

### 第 1 轮｜营销需求调研大师 陈述

核心结论：**本产品的真实客户不是买家，而是电商商家/运营团队**；买家只是被服务对象。
调研结论中最高价值的洞察是「同一句客服话术打给所有用户，是当前电商客服最大的效率浪费」，
标签人群分层不是锦上添花，而是这个 Agent 区别于通用客服机器人**唯一站得住的差异点**。
→ 详见 `docs/01-需求调研报告.md`

### 第 2 轮｜产品设计规划大师 陈述

将调研结论收敛为一条产品主线：**意图 → 人群 → 知识 → 话术 → 合规 → 兜底**。
明确提出「合规质检节点不可砍」——这是电商客服场景与通用问答机器人最大的产品差异，
也是商家愿意付费的风险对冲点。
→ 详见 `docs/02-产品方案.md`

### 第 3 轮｜技术研发专家 陈述

结论：**Dify 低代码路线与代码路线共用同一套配置（YAML）与同一套提示词（Markdown）**，
只是编排载体不同。核心逻辑零第三方依赖，`python -m unittest` 可直接跑通 23 个用例。
建议一期走 Dify（交付快、可演示），代码版作为"可控版"备选与兜底。
→ 详见 `docs/03-技术方案.md`

### 第 4 轮｜市场营销大师 陈述

明确本产品是**卖给商家的 B 端工具**，不是卖给买家的 C 端产品。
冷启动 0-30 天打法：不投品牌广告，先用 3 个垂直类目商家做标杆案例 + 效果对赌。
→ 详见 `docs/04-营销方案.md`

## 五、风险分级与预案

| 级别 | 风险 | 预案 |
|---|---|---|
| 高 | 话术合规事故（绝对化用语、超权限赔付） | 合规节点 block 级拦截 + 本地兜底替换 + 转人工三重防线 |
| 高 | 标签体系与商家 CRM 字段对不齐 | 一期只消费 7 个标准标签，缺失即兜底，不做推断 |
| 中 | 知识库质量差导致答非所问 | 检索置信度阈值 + 无命中转人工 |
| 中 | LLM 成本超预算 | 规则优先，仅低置信度才调 LLM |
| 低 | Dify 版本升级导致 DSL 不兼容 | 节点清单文档化，可 30 分钟内重建画布 |
