# 节点 2｜标签人群匹配提示词（规则兜底的补充说明）

> 使用位置：Dify「代码执行」节点 / 代码版 `src/tag_matcher.py`
> 本节点**不使用 LLM**，全部走 YAML 规则打分，原因见下方「为什么不用 LLM」

## 为什么不用 LLM 做人群匹配

1. 标签匹配是**确定性业务规则**，用 LLM 反而不可解释、不可复现；
2. 运营需要随时改权重（比如这个季度把「价格敏感」权重上调），LLM 改不了；
3. 人群策略出错会直接造成优惠券超发，必须可审计、可回滚。

## 规则结构

```yaml
rules:
  - field: value_level      # 对应 user.tags 的 key，或内置字段 intent
    op: equals              # equals / in / not_in / contains_any / gte / lte
    value: high
    weight: 40              # 命中即累加，最终取总分最高的画像
```

## 匹配算法（Dify 代码节点可直接复用）

```python
def match_persona(personas, threshold, default_id, fields):
    best = None
    for p in personas:
        score = sum(r["weight"] for r in p["rules"] if hit(r, fields))
        if score > 0 and (best is None or score > best["score"]):
            best = {"id": p["id"], "score": score, "strategy": p["strategy"]}
    if best and best["score"] >= threshold:
        return best
    return {"id": default_id, "score": 0, "strategy": fallback_strategy}
```

## 内置可匹配字段

| 字段 | 取值示例 | 来源 |
|---|---|---|
| lifecycle | new / active / silent / churn_risk | CRM 用户表 |
| value_level | high / medium / low | 近 12 月 GMV 分档 |
| price_sensitivity | sensitive / neutral / insensitive | 历史券使用率 |
| member_level | V0 ~ V5 | 会员体系 |
| source | live / search / private / content | 首次触达渠道 |
| service_pref | self_service / human / community | 历史工单渠道偏好 |
| emotion | anxious / angry / rational | 会话情绪识别（可接 LLM） |
| intent | 意图 id | 节点 1 输出 |

## 兜底原则

- 标签缺失 → 该条规则判不命中，**不做推断**，避免误伤；
- 全部不达标 → 回落 `general_fallback`，链路永不中断；
- 情绪标签（emotion）可由 LLM 会话情绪识别写入 `user.tags`，本节点只消费不生产。
